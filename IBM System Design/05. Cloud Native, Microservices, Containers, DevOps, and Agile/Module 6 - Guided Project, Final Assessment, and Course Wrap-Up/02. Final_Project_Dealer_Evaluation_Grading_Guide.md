### 🔹 Câu 3: Submit Two User Stories (mỗi story $\le$ 100 từ) (4 điểm)

#### **User Story 1: Triển khai lên IBM Cloud qua Code Engine**
```text
As a DevOps Engineer,
I need to deploy the containerized Dealer Evaluation application to IBM Cloud Code Engine,
so that the service is highly available, automatically scalable based on user traffic, and accessible globally without managing underlying virtual machine infrastructure.
```

#### **User Story 2: Đọc dữ liệu Product & Dealer từ JSON thay vì Hard-coded**
```text
As a Product Manager,
I need the application to load product and dealer information dynamically from an external JSON file instead of hard-coded source code,
so that pricing and product catalogs can be updated instantly without requiring code modifications, rebuilds, and redeployments.
```

### 🔹 Câu 4: Submit at least 3 benefits of deploying on IBM Cloud vs. in-house VMs (3 điểm)

Bạn có thể sao chép 3 lợi ích chuẩn sau:
1. **Automated Elasticity & Scalability (Khả năng Co giãn Tự động)**: IBM Cloud (Code Engine/Kubernetes) tự động tăng giảm tài nguyên (scale up/down, thậm chí scale-to-zero) theo lưu lượng truy cập thực tế mà không cần cấu hình thủ công phần cứng.
2. **High Availability & Multi-Zone Resilience (Tính Sẵn sàng Cao)**: Hệ thống được phân tán trên nhiều vùng sẵn sàng (Multi-Zone Regions), tự động phục hồi khi có lỗi phần cứng mà không làm gián đoạn dịch vụ.
3. **Reduced Operational Overhead & Maintenance (Giảm Chi phí Vận hành)**: Doanh nghiệp không cần tốn nhân lực cho việc bảo trì hạ tầng vật lý, nâng cấp phần cứng hay vá lỗi hệ điều hành (*OS patches*), giúp đội ngũ tập trung hoàn toàn vào logic nghiệp vụ sản phẩm.

---

### 🔹 Câu 5: Submit at least 3 reasons why hard-coding data in source code should be avoided (3 điểm)

Bạn có thể sao chép 3 lý do chuẩn sau:
1. **Lack of Flexibility & Deployment Overhead (Kém Linh hoạt)**: Mỗi khi cần thay đổi giá hoặc thêm sản phẩm, lập trình viên bắt buộc phải sửa mã nguồn, build lại toàn bộ ứng dụng và thực hiện quy trình deploy lại (*Rebuild & Redeploy*).
2. **Violation of Separation of Concerns (Vi phạm Nguyên lý Tách biệt)**: Trộn lẫn dữ liệu kinh doanh (*Business Data*) với logic ứng dụng (*Application Logic*) làm code trở nên cồng kềnh, khó đọc và khó mở rộng sang các nguồn dữ liệu bên ngoài như Database hay REST API.
3. **High Risk of Inconsistencies & Regression Bugs (Rủi ro Lỗi cao)**: Sửa đổi dữ liệu tĩnh trực tiếp trong mã nguồn dễ dẫn đến xung đột phiên bản khi nhiều người cùng làm việc và tiềm ẩn nguy cơ làm hỏng logic chức năng của ứng dụng.
