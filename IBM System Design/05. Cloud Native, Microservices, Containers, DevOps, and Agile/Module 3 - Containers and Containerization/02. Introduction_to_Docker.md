# Giới thiệu về Docker (Introduction to Docker)

Tài liệu này tóm tắt nội dung bài học **Introduction to Docker** trong **Module 3: Containers and Containerization** thuộc khóa học **Cloud Native, Microservices, Containers, DevOps, and Agile** do IBM cung cấp.

---

## 1. Docker là gì? (What is Docker?)

* **Thời điểm xuất hiện**: Ra mắt từ năm **2013**.
* **Định nghĩa chính thức**: Docker là một **nền tảng mở (Open Platform)** cho phép phát triển (*developing*), đóng gói/chuyển giao (*shipping*) và vận hành (*running*) các ứng dụng dưới dạng các container.
* **Ngôn ngữ phát triển**: Docker được viết bằng ngôn ngữ lập trình **Go (Golang)**.
* **Nguyên lý cốt lõi**: Docker cô lập hoàn toàn ứng dụng khỏi tầng hạ tầng bên dưới (bao gồm phần cứng, hệ điều hành máy chủ và container runtime).
* **Lý do Docker bùng nổ và phổ biến**:
  * **Kiến trúc đơn giản**: Dễ tiếp cận và sử dụng.
  * **Khả năng mở rộng quy mô lớn (Massive Scalability)**: Hỗ trợ co giãn linh hoạt theo nhu cầu.
  * **Tính di động vượt trội (Portability)**: Hoạt động đồng nhất trên nhiều nền tảng, môi trường (Cloud, On-Premises, Local) và vị trí địa lý khác nhau.

## 2. Công nghệ nền tảng & Quy trình hoạt động (Underlying Technology)

Docker tận dụng triệt để các tính năng có sẵn của **Linux Kernel** để vận hành:

### Công nghệ Namespaces (Isolated Workspace)
* Docker sử dụng công nghệ **Namespaces** trong Linux để tạo ra một không gian làm việc độc lập gọi là **Container**.
* Mỗi container khi khởi tạo sẽ được Docker gán cho một **tập hợp các namespaces riêng biệt (a set of namespaces)**.
* Mỗi khía cạnh tài nguyên của container (tiến trình PID, mạng Net, người dùng User, bộ nhớ Mount, IPC,...) đều chạy trong một namespace độc lập và chỉ được phép truy cập trong phạm vi giới hạn của namespace đó.

```
┌────────────────────────────────────────────────────────────────────────┐
│                              DOCKER ENGINE                             │
├────────────────────────────────────────────────────────────────────────┤
│   ┌──────────────────────────┐      ┌──────────────────────────┐       │
│   │       Container 1        │      │       Container 2        │       │
│   │ ┌──────────────────────┐ │      │ ┌──────────────────────┐ │       │
│   │ │ App Code & Libraries │ │      │ │ App Code & Libraries │ │       │
│   │ └──────────────────────┘ │      │ └──────────────────────┘ │       │
│   │  (Isolated Namespaces)   │      │  (Isolated Namespaces)   │       │
│   └──────────────────────────┘      └──────────────────────────┘       │
├────────────────────────────────────────────────────────────────────────┤
│                  Linux Kernel Features (Namespaces, cgroups)           │
├────────────────────────────────────────────────────────────────────────┤
│                          Host Operating System                         │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. Hệ sinh thái & Đổi mới công nghệ thúc đẩy bởi Docker

Phương pháp luận và thành công của Docker đã mở ra hàng loạt cải tiến và công cụ bổ trợ trong hệ sinh thái Cloud Native:

1. **Công cụ bổ trợ (Complementary Tools)**:
   * **Docker CLI**: Giao diện dòng lệnh thao tác trực tiếp với Docker Engine.
   * **Docker Compose**: Định nghĩa và chạy ứng dụng đa container (Multi-container apps).
   * **Prometheus**: Công cụ giám sát (Monitoring) và cảnh báo metric.
   * **Plugins**: Hệ thống plugin mở rộng linh hoạt (như *Storage Plugins*, *Network Plugins*).
2. **Công nghệ điều phối (Container Orchestration)**:
   * **Docker Swarm**
   * **Kubernetes (K8s)**
3. **Phương pháp luận phát triển hiện đại**:
   * Kiến trúc Vi dịch vụ (**Microservices**)
   * Điện toán không máy chủ (**Serverless**)

## 4. Các lợi ích cốt lõi của Docker (Key Benefits)

| Lợi ích | Mô tả chi tiết |
| :--- | :--- |
| **Môi trường nhất quán & Ổn định** | Môi trường cô lập loại bỏ hoàn toàn lỗi phát sinh do khác biệt cấu hình giữa máy Dev, Staging và Production. |
| **Triển khai siêu tốc (In Seconds)** | Khởi động và triển khai ứng dụng chỉ tính bằng giây thay vì vài chục phút như máy ảo (VM). |
| **Tối ưu dung lượng & Tái sử dụng** | Docker Images có kích thước nhỏ gọn và có thể tái sử dụng (qua các Layer), giúp tăng tốc đáng kể chu kỳ phát triển phần mềm. |
| **Tự động hóa & Giảm thiểu lỗi** | Khả năng tự động hóa đóng gói/triển khai giúp triệt tiêu sai sót thủ công và đơn giản hóa chu kỳ bảo trì hệ thống. |
| **Hỗ trợ Agile & CI/CD DevOps** | Tích hợp hoàn hảo vào các pipeline tự động hóa kiểm thử, build và deploy liên tục. |
| **Quản lý phiên bản (Versioning) dễ dàng** | Hỗ trợ gắn tag phiên bản cho Image, cho phép kiểm thử nhanh, dễ dàng Rollback và Redeploy khi xảy ra sự cố. |
| **Phân đoạn & Bảo trì linh hoạt** | Chia nhỏ ứng dụng để dễ dàng làm mới (refresh), dọn dẹp (cleanup) và sửa chữa (repair) mà không làm gián đoạn toàn bộ hệ thống. |
| **Độc lập nền tảng & Tính di động cao** | Docker Images độc lập với nền tảng, có thể chạy mượt mà ở bất kỳ đâu có Docker Engine. |

## 5. Khi nào KHÔNG NÊN sử dụng Docker? (When Docker is NOT a Good Fit)

Mặc dù rất mạnh mẽ, Docker không phải là giải pháp vạn năng cho mọi bài toán:

* 🚫 **Yêu cầu hiệu năng hoặc bảo mật phần cứng tối đa (High Performance / High Security)**: Ứng dụng cần truy cập trực tiếp phần cứng bare-metal ở mức độ thấp nhất mà không qua bất kỳ lớp trừu tượng nào.
* 🚫 **Kiến trúc nguyên khối cũ (Monolithic Architecture)**: Các ứng dụng monolith cồng kềnh, không được thiết kế dạng module hóa hoặc trạng thái phi phân tán.
* 🚫 **Ứng dụng có giao diện đồ họa phong phú (Rich GUI Features)**: Docker được tối ưu hóa cho dịch vụ nền (backend services, APIs, worker processes), không lý tưởng cho ứng dụng GUI nặng.
* 🚫 **Ứng dụng Desktop tiêu chuẩn hoặc chức năng hạn chế (Standard Desktop / Limited Functions)**: Các ứng dụng người dùng cá nhân thông thường không cần đến hạ tầng container phức tạp.

## 6. Tổng kết ghi nhớ nhanh (Key Takeaways)

1. **Docker** là nền tảng mở ra đời từ **2013**, viết bằng **Go**, phục vụ việc xây dựng, chuyển giao và chạy ứng dụng container.
2. Công nghệ cốt lõi giúp Docker cô lập là **Namespaces** của **Linux Kernel**.
3. Docker đóng vai trò bản lề cho **Agile**, **CI/CD** và **DevOps**.
4. Không phù hợp với ứng dụng **Monolith cồng kềnh**, ứng dụng **Desktop GUI** hoặc các hệ thống đòi hỏi **bảo mật/hiệu năng tuyệt đối cấp phần cứng**.
