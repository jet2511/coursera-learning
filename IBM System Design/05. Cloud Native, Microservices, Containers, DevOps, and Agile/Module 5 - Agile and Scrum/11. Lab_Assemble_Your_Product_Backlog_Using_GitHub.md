# Thực hành: Xây dựng Product Backlog trên GitHub (Lab: Assemble Your Product Backlog)

Tài liệu này hướng dẫn từng bước chi tiết bài thực hành **Lab: Assemble Your Product Backlog Using GitHub** trong **Module 5: Agile & Scrum** thuộc khóa học **Cloud Native, Microservices, Containers, DevOps, and Agile** do IBM cung cấp.

> **Thời lượng ước tính**: 20 phút  
> **Mục tiêu**: Tạo 7 User Stories bằng GitHub Issues, gán vào bảng Kanban và thực hành sắp xếp độ ưu tiên cho Product Backlog.

---

## BÀI TẬP 1: TẠO 7 USER STORIES BẰNG GITHUB ISSUES

Truy cập vào repository `lab-agile-planning` của bạn trên GitHub $\rightarrow$ Chuyển sang tab **Issues** $\rightarrow$ Bấm nút xanh **New issue**.

Tạo lần lượt 7 User Stories dưới đây (dùng định dạng `As a ..., I need ..., so that ...`):

### 1. Story 1: Bộ đếm cơ bản (Từ bài học)
* **Title**: `Need a service that has a counter`
* **Description**:
  ```text
  As a user,
  I need a service that has a counter,
  so that I can keep track of how many times something has been done.
  ```

### 2. Story 2: Hỗ trợ nhiều bộ đếm (Từ bài học)
* **Title**: `Must allow multiple counters`
* **Description**:
  ```text
  As a user,
  I need to have multiple counters,
  so that I can keep track of several counts at once.
  ```

### 3. Story 3: Lưu trữ dữ liệu khi restart (Từ bài học)
* **Title**: `Must persist counter across restarts`
* **Description**:
  ```text
  As a service provider,
  I need the service to persist the last known count,
  so that users don't lose track of their counts after the service is restarted.
  ```

### 4. Story 4: Đặt lại bộ đếm về 0 (Từ bài học)
* **Title**: `Counters can be reset`
* **Description**:
  ```text
  As a system administrator,
  I need the ability to reset the counter,
  so that I can redo counting from the start.
  ```

### 5. Story 5: Triển khai lên Cloud (Yêu cầu mới 1)
* **Title**: `Deploy service to the cloud`
* **Description**:
  ```text
  As a DevOps engineer,
  I need to deploy the service to the cloud,
  so that the application is highly available and accessible to users online.
  ```

### 6. Story 6: Xóa bộ đếm (Yêu cầu mới 2)
* **Title**: `Need the ability to remove a counter`
* **Description**:
  ```text
  As a user,
  I need the ability to remove a counter,
  so that I can delete counters that are no longer needed.
  ```

### 7. Story 7: Cập nhật giá trị bộ đếm (Yêu cầu mới 3)
* **Title**: `Need the ability to update a counter to a new value`
* **Description**:
  ```text
  As a system administrator,
  I need the ability to update a counter to a new value,
  so that I can correct inaccurate counts or adjust the starting number.
  ```

## CÁCH GÁN ISSUE VÀO BẢNG KANBAN

Sau khi điền Title và Description cho mỗi Issue:
1. Nhìn sang cột **phía bên phải** của màn hình tạo Issue $\rightarrow$ tìm mục **Projects**.
2. Bấm vào biểu tượng bánh răng ⚙️ bên cạnh chữ Projects $\rightarrow$ Chọn project **`Lab Agile Planning`**.
3. Chọn trạng thái cột **Status**: Chọn cột **`Backlog`** (hoặc `New Issues`).
4. Bấm nút **Submit new issue** để hoàn tất tạo Story.
5. Lặp lại thao tác cho đủ cả 7 User Stories.

*(Tùy chọn: Trong bảng Kanban, bạn có thể bấm vào dấu 3 chấm `...` ở cột `Backlog` $\rightarrow$ chọn **Set limit** $\rightarrow$ nhập `7` $\rightarrow$ bấm **Save**).*

## BÀI TẬP 2: SẮP XẾP ĐỘ ƯU TIÊN PRODUCT BACKLOG

Vào tab **Projects** $\rightarrow$ Chọn bảng **`Lab Agile Planning`**. Bạn sẽ thấy cả 7 User Stories đang nằm ở cột **`Backlog`**.

Tiến hành kéo-thả (*Drag & Drop*) các thẻ công việc vào các cột tương ứng theo kịch bản:

1. **`Need a service that has a counter`**:  
   $\longrightarrow$ Kéo sang **đỉnh trên cùng (Top)** của cột **`Product Backlog`** *(Ưu tiên cao nhất cho MVP)*.
2. **`Must allow multiple counters`**:  
   $\longrightarrow$ Kéo sang cột **`Icebox`** *(Chưa làm ngay trong các Sprint đầu)*.
3. **`Must persist counter across restarts`**:  
   $\longrightarrow$ Kéo sang cột **`Product Backlog`** *(Xếp phía dưới Story 1)*.
4. **`Counters can be reset`**:  
   $\longrightarrow$ Kéo sang cột **`Product Backlog`** *(Xếp phía dưới Story 3)*.
5. **3 Stories còn lại (`Deploy service to the cloud`, `Need the ability to remove a counter`, `Need the ability to update a counter`)**:  
   $\longrightarrow$ **Giữ nguyên ở cột `Backlog`** để chuẩn bị cho các bài lab sau.

## KẾT QUẢ HIỂN THỊ CÁC CỘT TRÊN BẢNG KANBAN

Sau khi hoàn thành sắp xếp:
* **Cột `Backlog`** (3 stories): `Deploy service to the cloud`, `Need the ability to remove a counter`, `Need the ability to update a counter to a new value`.
* **Cột `Icebox`** (1 story): `Must allow multiple counters`.
* **Cột `Product Backlog`** (3 stories theo thứ tự ưu tiên):
  1. `Need a service that has a counter` *(Top 1)*
  2. `Must persist counter across restarts` *(Top 2)*
  3. `Counters can be reset` *(Top 3)*
* **Các cột còn lại** (`Sprint Backlogs`, `In progress`, `Review/QA`, `Done`): Đang trống.
