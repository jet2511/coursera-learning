## 1. Khái niệm GraphQL (What is GraphQL?)

*   **GraphQL** là **ngôn ngữ truy vấn (*Query Language*) dành cho API**, được phát triển bởi **Facebook (Meta)** và phát hành dạng mã nguồn mở.
*   **Mục tiêu cốt lõi**: Cung cấp một giải pháp linh hoạt và hiệu quả hơn so với REST API truyền thống, cho phép ứng dụng client **chủ động định rõ chính xác dữ liệu mình cần (*request exactly what you need*)**.

---

## 2. So sánh Toàn diện: GraphQL vs. REST API

```
┌────────────────────────────────────────────────────────────────────────┐
│                          REST vs. GRAPHQL                              │
├──────────────────────────────────┬─────────────────────────────────────┤
│ REST: Nhiều Endpoints            │ GRAPHQL: 1 Endpoint Duy Nhất        │
│ • GET /orders/123                │ • POST /graphql                     │
│ • GET /users/456                 │   {                                 │
│ • GET /products/789              │     order(id: 123) {                │
│ -> Dữ liệu cố định, dư thừa      │       placedOn                      │
│    (Over-fetching) hoặc thiếu    │       products { name }             │
│    (Under-fetching)              │     }                               │
│                                  │   }                                 │
│                                  │ -> Lấy đúng trường cần thiết        │
└──────────────────────────────────┴─────────────────────────────────────┘
```

| Tiêu chí | REST API | GraphQL |
| :--- | :--- | :--- |
| **Cơ chế lấy dữ liệu** | Dễ bị **Over-fetching** (nhận thừa dữ liệu) hoặc **Under-fetching** (thiếu dữ liệu, phải gọi nhiều request) | **Precise fetching**: Lấy chính xác từng trường mong muốn |
| **Số lượng Endpoints** | Nhiều endpoints phân tán (`/orders`, `/users`, `/products`) | **Một endpoint duy nhất** (thường là `/graphql`) |
| **Cấu trúc phản hồi** | Cố định theo định nghĩa cứng từ backend | Linh hoạt, cấu trúc JSON trả về khớp với câu query của client |

## 3. Các Thuật Ngữ & Cú Pháp Cơ Bản trong GraphQL

### 1. Query (Truy vấn dữ liệu)
*   Dùng để **đọc/lấy dữ liệu** từ server (tương đương phương thức `GET` trong REST).
*   **Field (Trường)**: Đơn vị dữ liệu cụ thể được chỉ định bên trong query (ví dụ: `placedOn`, `name`).

```graphql
query Query { 
  order(id: 10908) { 
    placedOn 
    products { 
      name 
    } 
  } 
}
```

### 2. Mutation (Thay đổi dữ liệu)
*   Dùng để **tạo mới, cập nhật hoặc xóa dữ liệu** trên server (tương đương `POST`, `PUT`, `DELETE` trong REST).

```graphql
mutation newProduct { 
  createProduct(id: 145, name: "Pencil case", price: 1.99) { 
    success 
    errors 
  } 
}
```

## 4. Thách thức & Hạn chế Cần Lưu ý (GraphQL Challenges)

Mặc dù mang lại tính linh hoạt cao, GraphQL cũng đặt ra một số thách thức kỹ thuật:
1.  **Độ phức tạp trong thiết kế Schema**: Đòi hỏi lập kế hoạch và định nghĩa Schema chặt chẽ để tránh cấu trúc bị phình to, rối rắm.
2.  **Truy vấn lồng nhau quá sâu (*Deeply Nested Queries*)**: Nếu không được kiểm soát tốt (thiếu cơ chế giới hạn độ sâu truy vấn - *query depth limiting*), client có thể vô tình hoặc cố ý gửi các truy vấn phức tạp làm cạn kiệt tài nguyên máy chủ (*Performance Bottleneck / DoS*).
3.  **Bộ nhớ đệm (*Caching*) phức tạp**: REST tận dụng trực tiếp HTTP Caching chuẩn thông qua URL và HTTP Headers. Trong khi đó, GraphQL gửi toàn bộ request qua phương thức `POST` tới cùng một URL duy nhất, đòi hỏi các giải pháp caching phức tạp hơn ở cấp độ ứng dụng.

## 5. Nghiên Cứu Thực Tế: Netflix (Case Study)

*   **Vấn đề trước đây**: Ứng dụng Netflix trên các thiết bị khác nhau phải gọi hàng loạt REST API độc lập để tải dữ liệu cho từng khu vực trên màn hình (phim đề xuất, danh sách xu hướng, watchlist cá nhân,...).
*   **Giải pháp với GraphQL**:
    *   Tích hợp GraphQL làm tầng trung gian tổng hợp (*Aggregation Layer*) đứng trước các Microservices.
    *   Một truy vấn GraphQL duy nhất có thể gom dữ liệu từ nhiều microservices khác nhau và trả về dữ liệu tinh gọn cho từng loại thiết bị.
    *   **Kết quả**: Giảm thiểu tối đa số lượt truyền mạng (*round trips*), tiết kiệm băng thông, tăng tốc độ phản hồi và cho phép thay đổi schema backend mà không làm ảnh hưởng các ứng dụng client đang chạy.

---

## 6. Tóm tắt Điểm then chốt (Key Takeaways)

1.  **GraphQL là ngôn ngữ truy vấn cho API**, giải quyết triệt để vấn đề Over-fetching và Under-fetching của REST.
2.  **Cấu trúc chính**: Sử dụng `query` để đọc dữ liệu và `mutation` để thay đổi dữ liệu.
3.  **Ưu thế lớn**: Một endpoint duy nhất, gom dữ liệu từ nhiều microservices chỉ trong một round-trip.
4.  **Cần lưu ý**: Quản trị độ phức tạp của Schema, rủi ro truy vấn lồng sâu và bài toán Caching.
