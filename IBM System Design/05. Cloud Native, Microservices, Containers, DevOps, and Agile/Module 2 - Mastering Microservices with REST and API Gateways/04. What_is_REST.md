# Tổng quan về REST và RESTful API (What is REST?)

Tài liệu này tóm tắt nội dung bài học **What is REST?** trong **Module 2: Mastering Microservices with REST and API Gateways** thuộc khóa học **Cloud Native, Microservices, Containers, DevOps, and Agile** do IBM cung cấp.

---

## 1. Khái niệm REST (Representational State Transfer)

*   **REST** là một **phong cách kiến trúc (*architectural style*)** định nghĩa các nguyên tắc và ràng buộc trong việc giao tiếp giữa các ứng dụng qua mạng máy tính.
*   **Vị trí trong Microservices**: REST API cung cấp giải pháp tích hợp gọn nhẹ (*lightweight*), linh hoạt (*flexible*) và đã trở thành phương thức phổ biến nhất để liên kết các thành phần dịch vụ trong kiến trúc Microservices.

---

## 2. Ba Đặc Tính Cốt Lõi Của RESTful API (Key Characteristics)

Để một API được phân loại là **RESTful**, API đó phải đáp ứng 3 đặc tính cơ bản:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        3 ĐẶC TÍNH CỦA RESTful API                      │
├────────────────────────────────────────────────────────────────────────┤
│ 1. HTTP-Based Management                                               │
│    Quản lý toàn bộ yêu cầu qua giao thức HTTP và các phương thức chuẩn │
├────────────────────────────────────────────────────────────────────────┤
│ 2. Stateless Client-Server Communication                               │
│    Giao tiếp không trạng thái: Server không lưu session, Client tự giữ │
├────────────────────────────────────────────────────────────────────────┤
│ 3. Uniform Interface                                                   │
│    Giao diện đồng nhất: Mỗi tài nguyên định danh duy nhất qua một URI  │
└────────────────────────────────────────────────────────────────────────┘
```

### 1. Quản lý yêu cầu qua HTTP (HTTP Methods & CRUD)
REST API sử dụng các phương thức HTTP chuẩn để thực hiện các thao tác dữ liệu cơ bản (**CRUD - Create, Read, Update, Delete**):

| Phương thức HTTP | Thao tác CRUD tương ứng | Mục đích sử dụng |
| :--- | :--- | :--- |
| **POST** | **Create** | Tạo mới một tài nguyên/bản ghi |
| **GET** | **Read / Retrieve** | Đọc hoặc lấy dữ liệu của tài nguyên |
| **PUT** | **Update** | Cập nhật toàn bộ hoặc thay thế tài nguyên |
| **DELETE** | **Delete** | Xóa bỏ một tài nguyên |

### 2. Giao tiếp Không trạng thái (Stateless Nature)
*   **Nguyên tắc**: Mỗi yêu cầu từ Client gửi lên Server phải chứa **đầy đủ toàn bộ thông tin cần thiết** để Server có thể hiểu và xử lý yêu cầu đó.
*   **Không phụ thuộc Session trên Server**: Server không lưu giữ bất kỳ ngữ cảnh (*stored context*) hay trạng thái phiên (*session state*) nào giữa các lượt gọi. Trạng thái phiên được duy trì hoàn toàn phía Client.
*   **Lợi ích**: Giúp các dịch vụ Backend cực kỳ dễ dàng mở rộng quy mô (**Scalability**), vì bất kỳ server instance nào cũng có thể xử lý bất kỳ request nào mà không cần đồng bộ session cache.

### 3. Giao diện Đồng nhất (Uniform Interface)
*   Đảm bảo cấu trúc giao tiếp nhất quán bất kể yêu cầu xuất phát từ nền tảng nào (Web, Mobile, 3rd-party).
*   Mỗi đơn vị dữ liệu/tài nguyên thuộc về duy nhất một **Định danh Tài nguyên Thống nhất (*Uniform Resource Identifier - URI*)** (Ví dụ: `/products/123`).
*   Dữ liệu trả về cho tài nguyên phải cung cấp đầy đủ các thông tin cần thiết mà Client yêu cầu (ví dụ: tên sản phẩm, đơn giá, số lượng tồn kho,...).

## 3. Ví dụ Thực Tế: Sàn Giao Dịch Tiền Điện Tử CEX.IO

*   **Bối cảnh**: Sàn CEX.IO cung cấp REST API cho các nhà phát triển để tra cứu giá Bitcoin, các đồng tiền điện tử khác và dữ liệu sổ lệnh thị trường.
*   **Cấu trúc API**:
    *   Cung cấp tài liệu chi tiết về tham số yêu cầu (*request parameters*) và dữ liệu trả về (*response*).
    *   Dữ liệu truyền tải ở định dạng chuẩn hóa **JSON**.
    *   Hỗ trợ đa ngôn ngữ thông qua các đoạn mã mẫu: JavaScript, Python, C#, Java.
    *   *Ví dụ*: Gửi yêu cầu `GET` tới endpoint API công khai để lấy giá khớp lệnh gần nhất (*last price*) của một cặp giao dịch (như `BTC/USD`).

---

## 4. Tóm tắt Điểm then chốt (Key Takeaways)

1.  **REST là phong cách kiến trúc**, không phải một giao thức riêng lẻ, mà định hình cách các ứng dụng giao tiếp qua HTTP.
2.  **Stateless (Không trạng thái)**: Mỗi request độc lập và chứa đầy đủ dữ liệu, giúp Microservices dễ dàng mở rộng quy mô theo chiều ngang.
3.  **Uniform Interface & URI**: Quản lý tài nguyên qua định danh URI duy nhất và định dạng dữ liệu chuẩn (như JSON).
4.  **4 Phương thức HTTP kinh điển**: `GET` (đọc), `POST` (tạo), `PUT` (sửa), `DELETE` (xóa).
