# Giới thiệu về API Gateway (Introduction to API Gateway)

Tài liệu này tóm tắt nội dung bài học **Introduction to API Gateway** trong **Module 2: Mastering Microservices with REST and API Gateways** thuộc khóa học **Cloud Native, Microservices, Containers, DevOps, and Agile** do IBM cung cấp.

## 1. Khái niệm API Gateway (What is an API Gateway?)

*   **Định nghĩa**: **API Gateway** là một công cụ quản lý API (*API management tool*) đóng vai trò làm cổng vào trung gian nằm giữa người dùng (*Client*) và tập hợp các dịch vụ backend (*Microservices*).
*   **Cơ chế cốt lõi**:
    *   Đóng vai trò là **Điểm tiếp xúc duy nhất (*Single Point of Contact*)** tiếp nhận mọi yêu cầu từ bên ngoài.
    *   **Gom cụm & Tổng hợp (*Aggregates*)**: Điều phối các yêu cầu đến các microservices tương ứng để xử lý và tổng hợp dữ liệu trả về một phản hồi duy nhất cho Client.

```
                  ┌───────────────────────────────┐
                  │    Clients (Web / Mobile)     │
                  └───────────────┬───────────────┘
                                  │
                                  ▼ (Single Request / Round Trip)
                  ┌───────────────────────────────┐
                  │          API GATEWAY          │
                  │  • Authentication & Rate Limit│
                  │  • Routing & Aggregation      │
                  │  • Analytics & Monitoring     │
                  └───────┬───────┬───────┬───────┘
                          │       │       │
             ┌────────────┘       │       └────────────┐
             ▼                    ▼                    ▼
    ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐
    │ Product Service │  │Inventory Service│  │  Order Service  │
    └─────────────────┘  └─────────────────┘  └─────────────────┘
```

## 2. Vì sao cần sử dụng API Gateway? (Core Use Cases)

Khi một hệ thống thương mại điện tử (E-Commerce) chuyển sang microservices, nó có thể bao gồm: *Product Service*, *Inventory Service*, *Order Service*, *Auth Service*,... Nếu Client phải tương tác trực tiếp với từng service, hệ thống sẽ cực kỳ phức tạp.

API Gateway giải quyết các bài toán sau:
1.  **Bảo mật & Giới hạn tải (*Security & Rate Limiting*)**: Bảo vệ backend khỏi các cuộc tấn công, lạm dụng hoặc quá tải lưu lượng thông qua cơ chế xác thực và hạn chế tần suất gọi (*rate limiting*).
2.  **Giám sát & Phân tích (*Analytics & Monitoring*)**: Theo dõi cách thức, tần suất sử dụng và tình trạng sức khỏe của các API.
3.  **Thương mại hóa API (*Monetization & Billing*)**: Tích hợp các hệ thống tính cước cho các bên tiêu thụ API.
4.  **Trừu tượng hóa & Tách biệt (*Decoupling & Abstraction*)**: Cho phép đội ngũ backend tự do thay đổi địa chỉ IP máy chủ, tăng/giảm số lượng instance, hoặc thay thế một service cũ bằng service mới mà không làm gián đoạn hay ảnh hưởng tới Client.

## 3. Lợi ích của API Gateway (Benefits)

*   **Đơn giản hóa Client (*Client Simplification*)**: Loại bỏ logic phức tạp (gọi nhiều API tuần tự, tổng hợp dữ liệu) khỏi client và chuyển toàn bộ việc đó về API Gateway.
*   **Giảm số lượng Request/Round Trips**: Cho phép Client lấy toàn bộ dữ liệu cần thiết từ nhiều microservices chỉ qua **một lượt gửi request duy nhất (*single round trip*)**.
*   **Cung cấp API tối ưu cho từng Client**: Hỗ trợ định dạng và tối ưu luồng dữ liệu phù hợp với từng thiết bị (Web Desktop, Mobile App, IoT).
*   **Chuẩn hóa Giao thức Giao tiếp (*Protocol Standardization*)**: Cung cấp giao thức chuẩn (như HTTP/REST) ra bên ngoài, bất kể nội bộ các microservice giao tiếp với nhau bằng giao thức nào (gRPC, Message Brokers,...).

---

## 4. Hạn chế & Thách thức (Drawbacks)

*   **Tăng khối lượng quản trị**: Là một thành phần hạ tầng bổ sung cần phải phát triển, cấu hình và vận hành liên tục.
*   **Nguy cơ Điểm lỗi đơn lẻ (*Single Point of Failure - SPOF*)**: Nếu API Gateway gặp sự cố mà không có cơ chế dự phòng chịu lỗi (High Availability), toàn bộ ứng dụng sẽ bị tê liệt.
*   **Tăng độ trễ mạng (*Latency*)**: Làm tăng nhẹ thời gian phản hồi (*response time*) do yêu cầu phải đi qua thêm một chặng trung gian (*additional network hop*).

## 5. Các Sản phẩm API Gateway Phổ biến

| Loại hình | Sản phẩm tiêu biểu | Đặc điểm nổi bật |
| :--- | :--- | :--- |
| **Dịch vụ Đám mây / Managed** | **IBM DataPower Gateway** | Cổng ứng dụng hàng đầu ngành về bảo mật cấp doanh nghiệp (*high-security enterprise*). |
| | **Google Apigee / Cloud Endpoints** | Quản lý toàn diện API trên hệ sinh thái Google Cloud. |

| **Mã nguồn mở (Open-Source)** | **Kong** | API Gateway mã nguồn mở phổ biến và được sử dụng nhiều nhất hiện nay. |

| | **Tyk** | Cung cấp cả bản mã nguồn mở và bản thương mại (managed version). |
| | **Gloo** | Xây dựng trên nền tảng Envoy Proxy, hỗ trợ tốt cho Kubernetes và Service Mesh. |

## 6. Tóm tắt Điểm then chốt (Key Takeaways)

1.  **API Gateway là "cánh cửa" duy nhất** dẫn vào hệ sinh thái microservices backend.
2.  **Ẩn giấu sự phức tạp** của hệ thống phân tán và bảo vệ backend thông qua Authentication & Rate Limiting.
3.  **Tối ưu trải nghiệm Client**: Giảm số lượng request và round trips bằng cơ chế gom cụm và tổng hợp (*aggregation*).
4.  Cần cân nhắc bài toán về **độ trễ (Latency)** và **tính sẵn sàng cao (High Availability)** để tránh biến Gateway thành điểm lỗi đơn lẻ (SPOF).
