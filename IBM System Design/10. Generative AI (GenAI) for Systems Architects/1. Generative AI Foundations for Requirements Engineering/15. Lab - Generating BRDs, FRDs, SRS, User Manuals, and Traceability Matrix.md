# Lab: Generating BRDs, FRDs, SRS, User Manuals, and Traceability Matrix

## Tóm tắt quy trình bài Lab
1. **Exercise 1 — Tạo bộ 4 tài liệu chuẩn từ Interview Transcript:**
   - **BRD (Business Requirements Document):** Góc nhìn kinh doanh (Executive Summary, Business Goals, Scope, Stakeholders, High-level Requirements, Success Criteria, Risks/Constraints).
   - **FRD (Functional Requirements Document):** Góc nhìn chức năng dựa trên BRD (Feature List, User Stories, Use Cases, UI & Data Requirements).
   - **SRS (Software Requirements Specification):** Góc nhìn kỹ thuật dựa trên BRD + FRD (System Overview, Technical Architecture, Detailed Technical Specs, Performance/Security, Acceptance Criteria, Traceability).
   - **User Manual:** Hướng dẫn người dùng cuối bằng ngôn ngữ đơn giản, không thuật ngữ kỹ thuật (Getting Started, Step-by-Step, Troubleshooting, FAQs).
2. **Exercise 2 — Tạo Traceability Matrix:**
   - Liên kết xuyên suốt `BRD ID → FRD ID → SRS ID → User Manual Section` để kiểm tra độ phủ, phát hiện yêu cầu bị sót hoặc tính năng thừa không gắn với mục tiêu kinh doanh.

## Bài giải mẫu (Áp dụng kịch bản Mobile Banking App từ Lab trước)

### Exercise 1: Bộ 4 tài liệu mẫu (Rút gọn chuẩn cấu trúc)

#### 1. BRD (Business Requirements Document)
- **Executive Summary:** Nâng cấp luồng chuyển khoản trên Mobile Banking App nhằm giảm thời gian thao tác và loại bỏ lỗi giao dịch trùng lặp do độ trễ Core Banking.
- **Business Goals:**
  - `BR-001`: Rút ngắn thời gian chuyển khoản từ 45 giây xuống **< 20 giây** (tối đa 3 bước).
  - `BR-002`: Đạt tỷ lệ hoàn thành giao dịch **> 95%** và **0% lỗi giao dịch trùng lặp** vào giờ cao điểm.
- **Project Scope:** Tối ưu UI/UX luồng chuyển khoản, bổ sung cơ chế chống trùng lặp (Idempotency) và xác thực MFA/sinh trắc học. (Ngoài phạm vi: tính năng chia tiền nhóm).
- **Key Stakeholders:** Product Manager (Alex), End-users, Core Banking Team, Security/Compliance Team.
- **Risks & Constraints:** Core Banking cũ có độ trễ cao vào khung giờ 11h–13h và cuối tháng; bắt buộc tuân thủ MFA.

#### 2. FRD (Functional Requirements Document)
- **FR-001 (Liên kết BR-001) — Luồng chuyển khoản 3 bước:**
  - *User Story:* As a customer, I want to complete a transfer in 3 steps, so that I can send money quickly.
  - *Use Case:* Nhập người nhận & số tiền → Xem lại & xác thực sinh trắc học → Nhận kết quả.
- **FR-002 (Liên kết BR-002) — Khóa nút gửi & Hiển thị trạng thái:**
  - *User Story:* As a customer, I want the Send button to lock and show a processing state after tapping, so that I don't submit duplicate transfers.
  - *UI Requirement:* Vô hiệu hóa nút "Gửi" ngay lập tức, hiển thị spinner + thông báo *"Đang xử lý..."*.

#### 3. SRS (Software Requirements Specification)
- **SRS-001 (Liên kết FR-001, BR-001) — Tối ưu API & Caching:**
  - *Technical Spec:* Sử dụng API Gateway + Redis cache cho danh sách người nhận thường xuyên; thời gian phản hồi UI < 500ms, tổng luồng < 20s.
  - *Security:* Bắt buộc xác thực sinh trắc học/OTP (MFA) trước khi ký giao dịch.
- **SRS-002 (Liên kết FR-002, BR-002) — Cơ chế Idempotency:**
  - *Technical Spec:* Client sinh `idempotency_key` (UUID v4) cho mỗi phiên chuyển khoản. Backend lưu key vào Redis với TTL 5 phút; từ chối mọi request trùng key bằng HTTP `409 Conflict` hoặc trả về trạng thái giao dịch gốc.
  - *Acceptance Criteria:* Nút Submit khóa ngay sau 1 lần chạm; 100% request trùng key trong 5 phút không tạo giao dịch thứ hai ở Core Banking.

#### 4. User Manual (Hướng dẫn người dùng)
- **Mục 1.1 — Chuyển khoản nhanh trong 3 bước:**
  1. Chọn **Chuyển tiền**, nhập số tài khoản và số tiền.
  2. Kiểm tra thông tin và xác nhận bằng **Vân tay / Face ID**.
  3. Chờ màn hình xác nhận thành công.
- **Mục 1.2 — Xử lý khi mạng chậm (Troubleshooting):**
  - Nếu thấy thông báo *"Đang xử lý..."*, vui lòng **không thoát ứng dụng hoặc bấm gửi lại**. Hệ thống sẽ tự động bảo vệ bạn khỏi việc chuyển trùng tiền.
