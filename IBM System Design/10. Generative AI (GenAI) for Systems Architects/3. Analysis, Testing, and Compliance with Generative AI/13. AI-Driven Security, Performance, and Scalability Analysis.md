# Tóm tắt: AI-Driven Security, Performance, and Scalability Analysis

## 1. Đánh giá Lỗ hổng Bảo mật theo Quy trình Hệ thống (Security Vulnerability Assessment)
* **Quy trình 4 bước chuẩn:**
  1. **Document Ingestion:** Thu thập tài liệu kỹ thuật (user flows, bảng phân quyền, API spec, code snippets), làm sạch dữ liệu thừa.
  2. **Prompt Engineering:** Tạo prompt mục tiêu hướng AI tìm kiếm rủi ro cụ thể (xác thực yếu, truyền tin không mã hóa, lộ API nhạy cảm).
  3. **Pattern Matching:** Đối chiếu với các mẫu tấn công phổ biến (SQL Injection, XSS, Leo thang đặc quyền - Privilege Escalation).
  4. **Result Synthesis:** Xuất báo cáo rủi ro kèm giải pháp khắc phục (remediations) tương ứng.
* **Ví dụ thực tế:**
  - *Code snippet:* Hàm `validate_password` chỉ kiểm tra độ dài `< 8` ký tự -> AI phát hiện thiếu ràng buộc ký tự đặc biệt, chữ số, chữ hoa và thiếu kiểm tra đối chiếu cơ sở dữ liệu rò rỉ (breach database).
  - *User flow:* Phát hiện luồng reset password không có MFA -> Tăng nguy cơ chiếm quyền tài khoản (Account takeover).

## 2. Bóc tách Điểm nghẽn Hiệu năng từ Tài liệu Kiến trúc (Performance Bottleneck Extraction)
* **Quy trình phân tích:**
  - Thu thập sơ đồ kiến trúc, luồng dữ liệu (data flows) và hành trình người dùng quan trọng.
  - Hướng prompt tìm các thành phần chạy đơn luồng (single-threaded), tranh chấp ghi cơ sở dữ liệu (write contention) hoặc gọi API đồng bộ (synchronous calls) gây nghẽn.
* **Đầu ra hành động:**
  - *Ví dụ:* Dịch vụ xử lý đơn hàng dùng 1 database duy nhất cho toàn bộ tác vụ ghi -> AI đề xuất áp dụng **Database Sharding** hoặc bổ sung hàng đợi ghi (**Write Queue**).
  - Tối ưu hàm `fetchData()` tuần tự sang cơ chế **Batching** hoặc bất đồng bộ.

## 3. Chuyển đổi Tài liệu Kỹ thuật thành Kế hoạch Mở rộng (Scalability Planning)
* **Kỹ thuật Prompting:**
  - *"Transform the following technical specification into a phased scalability roadmap, outlining resource milestones and risk mitigation strategies for each phase."*
  - *"Based on the provided user growth estimates, recommend infrastructure changes needed to support 5x scale over the next 12 months."*
* **Lộ trình phân kỳ (Phased Roadmap) từ 10.000 lên 100.000 users:**
  - *Giai đoạn 1 (0–6 tháng):* Chuyển đổi sang môi trường Cloud Autoscaling, chuyển sang Stateless Application Servers.
  - *Giai đoạn 2 (6–12 tháng):* Triển khai sharding DB theo chiều ngang, phân tán bộ nhớ đệm (Distributed Caching), tích hợp CDN cho tài nguyên tĩnh, tự động hóa hạ tầng bằng IaC (Terraform/CloudFormation).

## 4. Khung Tạo Kịch bản Kiểm thử Áp lực bằng AI (Stress-Test Framework)
* **4 trụ cột thiết kế kịch bản Stress-test:**
  1. **Parameter Extraction:** Trích xuất tải đỉnh (peak load), mức độ đồng thời (concurrency levels) và luồng nghiệp vụ trọng yếu.
  2. **Scenario Creation:** Lập bản thiết kế kiểm thử chi tiết.
  3. **Benchmark Definition:** Xác lập ngưỡng Đạt/Không đạt (Pass/Fail criteria) dựa trên SLA/SLO.
  4. **Failure Point Identification:** Dự báo trước điểm dễ gãy đổ nhất (ví dụ: service ngốn RAM, nút thắt mạng, dịch vụ thanh toán khi tải duy trì liên tục).
* **Prompt tiêu biểu:**
  - *"Based on the following workflow, create stress-test scenarios that simulate 5x peak user activity. Identify database, API, and network points that should be monitored for latency or errors."*
* **Ví dụ E-commerce:** Giả lập 10.000 checkout đồng thời/phút -> Giám sát thời gian ghi DB và độ trễ phản hồi API -> Điểm gãy kỳ vọng: Payment processing service.
