# Glossary: Non-Functional Requirements (Thuật ngữ Yêu cầu Phi chức năng)

Bảng thuật ngữ chuyên ngành chuẩn hóa (kèm giải thích chi tiết tiếng Việt và ngữ cảnh hệ thống):

| Thuật ngữ (Term) | Định nghĩa gốc (Definition) | Giải thích & Ngữ cảnh kỹ thuật (Vietnamese) |
| :--- | :--- | :--- |
| **Active/Active model** | A disaster recovery strategy where multiple production environments run simultaneously across regions, ensuring near-zero downtime at a higher operational cost. | Mô hình DR chạy đồng thời nhiều môi trường production hoàn chỉnh trên các region khác nhau; downtime gần như bằng 0; chi phí cao nhất. |
| **Application layer** | The system level where code executes and user-facing logic operates; optimization improves responsiveness and resource efficiency. | Tầng ứng dụng: nơi thực thi code nghiệp vụ (business logic); tối ưu tầng này giúp phản hồi nhanh và dùng tài nguyên hiệu quả. |
| **Application metrics** | Performance indicators that assess response times, error rates, throughput, and queue durations to evaluate application health. | Các chỉ số đo lường sức khỏe ứng dụng: thời gian phản hồi (response time), tỷ lệ lỗi (error rate), thông lượng (throughput), độ dài hàng đợi. |
| **Asynchronous processing** | Executing non-critical tasks independently from the main process flow to prevent delays in user interactions. | Xử lý bất đồng bộ: đẩy các tác vụ không gấp ra khỏi luồng chính (background worker) để người dùng không phải chờ đợi phản hồi. |
| **Auto-Scaling** | Automated adjustment of computing resources based on current demand to maintain performance and cost efficiency. | Cơ chế tự động co giãn tài nguyên điện toán (CPU/RAM/Nodes) theo nhu cầu tải thực tế để đảm bảo hiệu năng và tối ưu chi phí. |
| **Availability** | The degree to which a system remains operational and accessible; often expressed as uptime percentage (e.g., 99.9%). | Độ sẵn sàng: tỷ lệ thời gian hệ thống hoạt động bình thường và truy cập được, thường đo bằng số 9 (ví dụ: 99.9% uptime). |
| **Backup and restore** | The simplest disaster recovery model that stores snapshots of data and infrastructure for later restoration after a failure. | Chiến lược DR cơ bản nhất: định kỳ chụp snapshot dữ liệu và hạ tầng để khôi phục lại khi gặp sự cố; RTO/RPO tính bằng giờ. |
| **Batching** | Combining multiple operations into a single process to reduce overhead and improve system speed. | Kỹ thuật gom nhiều thao tác/request nhỏ lẻ thành một đợt xử lý lớn nhằm giảm tải I/O và network overhead. |
| **Business metrics** | Quantitative measures like transaction rates, revenue per hour, or conversion rates that gauge business performance through system behavior. | Chỉ số đo lường hiệu quả kinh doanh thông qua hành vi hệ thống: số giao dịch/giây, doanh thu/giờ, tỷ lệ chuyển đổi (conversion rate). |
| **Caching** | Storing frequently accessed data temporarily to accelerate retrieval and reduce database load. | Lưu tạm dữ liệu thường xuyên đọc vào bộ nhớ nhanh (RAM: Redis, Memcached) để tăng tốc độ truy xuất và giảm tải cho Database. |
| **Capacity planning** | The process of balancing current resource supply with projected demand to ensure performance and cost optimization. | Hoạch định công suất: dự báo và cân bằng cung - cầu tài nguyên nhằm tối ưu hiệu năng và khống chế chi phí hạ tầng. |
| **Chatty APIs** | Interfaces that make excessive network calls between services, often increasing latency and reducing scalability. | API "lắm lời": các dịch vụ gọi nhau quá nhiều lần với payload nhỏ, gây tăng đột biến độ trễ mạng (latency) và nghẽn hệ thống. |
| **Cloud backup** | Off-site data storage in cloud environments for redundancy and disaster resilience. | Sao lưu dữ liệu lên đám mây (off-site) để dự phòng thảm họa tại chỗ. |
| **Core web vitals** | Google-defined metrics that measure page performance and user experience factors such as loading, interactivity, and visual stability. | Bộ chỉ số đo lường trải nghiệm trang web của Google: tốc độ tải (LCP), tính tương tác (INP/FID) và độ ổn định giao diện (CLS). |
| **CPU utilization** | A metric representing the percentage of processor resources currently used on a system or server. | Tỷ lệ phần trăm tài nguyên vi xử lý đang được sử dụng trên máy chủ. |
| **Database layer** | The foundational system layer managing data retrieval, storage, and indexing; optimization often yields significant performance gains. | Tầng cơ sở dữ liệu: lưu trữ, truy xuất và lập chỉ mục dữ liệu; tối ưu tầng này thường đem lại hiệu năng vượt trội nhất cho toàn hệ thống. |
| **Data encryption** | The process of converting information into a secure format that prevents unauthorized access during storage or transmission. | Mã hóa dữ liệu: chuyển đổi dữ liệu thành dạng mã an toàn (chống truy cập trái phép) cả khi lưu trữ (at rest) và khi truyền tải (in transit). |
| **Disaster recovery (DR)** | A structured approach ensuring business continuity by restoring systems and data after a failure or disruption. | Khắc phục thảm họa: quy trình có cấu trúc nhằm khôi phục hệ thống và dữ liệu để đảm bảo hoạt động kinh doanh liên tục sau sự cố lớn. |
| **Downtime** | The total period when a service or application is unavailable or non-functional. | Thời gian chết: khoảng thời gian dịch vụ/hệ thống bị sập hoặc không thể phục vụ người dùng. |
| **Elastic Compute Cloud (EC2)** | An AWS service that provides resizable virtual server capacity for scalable computing. | Dịch vụ máy chủ ảo có thể thay đổi kích thước linh hoạt của AWS. |
| **Error rate** | The proportion of failed transactions or requests in a system, indicating reliability or stability issues. | Tỷ lệ lỗi: tỷ lệ phần trăm các request/giao dịch bị thất bại trên tổng số request. |
| **Functional requirements** | Specifications detailing a system’s actions, including features and user interactions. | Yêu cầu chức năng: mô tả hệ thống **làm gì** (tính năng, nghiệp vụ, tương tác người dùng). |
| **Forecasting** | The process of predicting future resource requirements based on historical usage data and projected business demand. | Dự báo nhu cầu tài nguyên trong tương lai dựa trên dữ liệu lịch sử và kế hoạch kinh doanh. |
| **Full-text search** | The ability to efficiently query databases for words or phrases across document content. | Tìm kiếm toàn văn: khả năng tìm kiếm từ/cụm từ bên trong nội dung văn bản một cách tối ưu (ví dụ: Elasticsearch). |
| **Golden signals** | Four key system health indicators promoted by Google SRE: latency, traffic, errors, and saturation. | 4 tín hiệu vàng trong giám sát hệ thống (Google SRE): **Latency** (độ trễ), **Traffic** (lưu lượng), **Errors** (lỗi), **Saturation** (độ bão hòa tài nguyên). |
| **High availability (HA)** | System design that ensures minimal downtime and continuous operation through redundancy and failover. | Tính sẵn sàng cao: thiết kế hệ thống đảm bảo giảm thiểu tối đa downtime thông qua cơ chế dự phòng (redundancy) và tự chuyển đổi lỗi (failover). |
| **Horizontal scaling** | Adding more machines or instances to distribute load evenly and improve capacity. | Mở rộng theo chiều ngang (Scale out): bổ sung thêm nhiều máy chủ chạy song song để chia sẻ tải. |
| **Immutable backup** | A data copy that cannot be altered or deleted, ensuring protection against ransomware or corruption. | Bản sao lưu bất biến: dữ liệu backup ở trạng thái chỉ đọc (WORM), không thể bị sửa, xóa hay ghi đè; chống mã độc tống tiền (ransomware). |
| **Indexing** | Creating data structures to improve query speed and database read efficiency. | Đánh chỉ mục: tạo cấu trúc dữ liệu tra cứu nhanh (như B-Tree) để tăng tốc độ truy vấn đọc và tránh Full Table Scan. |
| **Infrastructure as Code (IaC)** | Managing and provisioning infrastructure through code to ensure repeatability, consistency, and automation. | Quản lý hạ tầng bằng mã: định nghĩa và cấp phát máy chủ, mạng qua code (Terraform, CloudFormation) để nhất quán và tự động hóa. |
| **Infrastructure metrics** | Monitoring CPU, memory, disk, and network performance indicators at the hardware or virtualization level. | Chỉ số hạ tầng: đo đạc CPU, RAM, Disk I/O, Network I/O ở tầng phần cứng hoặc ảo hóa. |
| **Integration** | The ability of a system to connect and interact with other applications through APIs or data synchronization. | Khả năng tích hợp: mức độ hệ thống liên kết và trao đổi dữ liệu với ứng dụng khác qua API hoặc đồng bộ hóa. |
| **Latency** | The delay between a user action or request and the system’s response, often measured in milliseconds. | Độ trễ: khoảng thời gian từ lúc gửi yêu cầu đến khi nhận được phản hồi (thường tính bằng mili-giây, ms). |
| **Lead strategy** | A capacity planning approach that adds resources before demand increases, minimizing performance risk but increasing cost. | Chiến lược đón đầu: chủ động bổ sung tài nguyên trước khi tải tăng; triệt tiêu rủi ro sập hệ thống nhưng chi phí cao. |
| **Load balancer** | A network device or software system that distributes incoming requests across multiple servers for optimal resource use. | Bộ cân bằng tải: thiết bị/phần mềm phân bổ lưu lượng truy cập đồng đều đến các máy chủ backend. |
| **Logs** | Recorded system events providing detailed context for understanding operations, debugging, or tracing issues. | Bản ghi nhật ký: lưu lại các sự kiện có ngữ cảnh trong hệ thống phục vụ việc debug và phân tích nguyên nhân. |
| **Match strategy** | A capacity management approach that adjusts resources incrementally to meet measurable demand changes. | Chiến lược bám sát: điều chỉnh tăng/giảm tài nguyên từng bước nhỏ tương ứng với nhu cầu tải thực tế đo được. |
| **Memory utilization** | The percentage of memory resources currently used by system processes, indicating performance or capacity strain. | Mức sử dụng bộ nhớ RAM của các tiến trình hệ thống. |
| **Microservices** | An architectural style that divides an application into loosely coupled services that can be developed, deployed, and scaled independently. | Kiến trúc vi dịch vụ: chia nhỏ ứng dụng thành các dịch vụ độc lập, kết nối lỏng (loosely coupled), có thể scale và deploy riêng rẽ. |
| **Metrics** | Quantitative data collected over time to measure the health and performance of systems or applications. | Dữ liệu định lượng được thu thập theo chuỗi thời gian để đo lường sức khỏe hệ thống. |
| **Monitoring** | Continuous observation of system metrics, logs, and traces to detect issues and assess performance. | Giám sát liên tục: theo dõi metrics, logs, traces để phát hiện sớm các dấu hiệu bất thường. |
| **Non-functional requirements (NFRs)** | Specifications describing system qualities—like performance, scalability, and security—defining how well it performs. | Yêu cầu phi chức năng: tiêu chuẩn đo lường chất lượng hệ thống (**hệ thống hoạt động tốt như thế nào** - bảo mật, hiệu năng, mở rộng...). |
| **Observability** | The practice of understanding a system’s internal state by analyzing metrics, logs, and traces. | Khả năng quan sát: thấu hiểu trạng thái bên trong hệ thống thông qua dữ liệu đầu ra bên ngoài (Metrics, Logs, Traces). |
| **Performance metrics** | Measurements such as response time, throughput, and uptime are used to assess application speed and reliability. | Chỉ số hiệu năng: phản ánh tốc độ và độ tin cậy của ứng dụng (response time, throughput, uptime). |
| **Pilot light** | A partial disaster recovery setup where core components remain active, allowing faster activation during outages. | Mô hình DR duy trì database cốt lõi đồng bộ liên tục trong khi các compute instances ở trạng thái tắt, bật lên khi có sự cố (RTO < 1h). |
| **Reliability** | The ability of a system to function correctly and recover from failures without data loss or downtime. | Độ tin cậy: khả năng hệ thống duy trì hoạt động chính xác và tự phục hồi khi có lỗi mà không làm mất mát dữ liệu. |
| **Replication** | The process of duplicating data across multiple databases or servers to enhance availability, reliability, and disaster recovery readiness. | Nhân bản dữ liệu: sao chép đồng bộ/bất đồng bộ dữ liệu sang nhiều database/server để tăng tính sẵn sàng và dự phòng thảm họa. |
| **Resource utilization rate** | The percentage of available system resources (such as CPU, memory, network bandwidth, or storage) currently in use, indicating how efficiently a system is operating. | Tỷ lệ sử dụng tài nguyên: tỷ lệ % CPU, RAM, băng thông hoặc ổ cứng đang dùng trên tổng tài nguyên khả dụng. |
| **Response time** | The duration a system takes to complete a request, often used to gauge user experience quality. | Thời gian phản hồi: tổng thời gian hoàn tất một request, chỉ số cốt lõi đánh giá trải nghiệm người dùng. |
| **Recovery point objective (RPO)** | The maximum tolerable period of data loss measured in time. | Giới hạn mất mát dữ liệu tối đa chấp nhận được (tính bằng mốc thời gian, ví dụ mất dữ liệu tối đa 4 giờ). |
| **Recovery time objective (RTO)** | The maximum acceptable time a service can remain unavailable after an incident. | Giới hạn thời gian gián đoạn (downtime) tối đa chấp nhận được để phục hồi hệ thống trở lại. |
| **REST API** | An interface that enables systems to exchange data over HTTP using standardized resource operations. | Giao diện lập trình ứng dụng truyền tải dữ liệu qua HTTP với các phương thức chuẩn (GET, POST, PUT, DELETE). |
| **Root cause analysis (RCA)** | The process of identifying the primary source of a failure or performance issue through trace and log analysis. | Phân tích nguyên nhân gốc rễ: quy trình tìm kiếm nguồn gốc sâu xa gây ra sự cố qua logs và traces. |
| **Scalability** | The ability of a system to handle increasing workload or user demand while maintaining performance and stability. | Khả năng mở rộng: năng lực chịu tải tăng dần mà vẫn giữ vững hiệu năng và tính ổn định. |
| **Security metrics** | Measurements that assess the strength of system protection mechanisms, tracking failed logins, vulnerabilities, and attack attempts. | Chỉ số an ninh: đo lường khả năng phòng vệ của hệ thống (số lần login thất bại, lỗ hổng, tần suất bị tấn công). |
| **Serverless computing** | Cloud infrastructure where resources automatically scale based on demand without manual provisioning. | Điện toán không máy chủ: hạ tầng tự động co giãn theo từng request mà kỹ sư không cần cấu hình hoặc quản lý server. |
| **Sharding** | A database partitioning technique that divides large datasets into smaller, distributed segments (shards) stored across multiple machines to improve scalability and query performance. | Phân mảnh cơ sở dữ liệu: chia nhỏ một bảng/database khổng lồ thành nhiều phần nhỏ (shards) lưu trên các máy chủ khác nhau để mở rộng quy mô. |
| **Stateless architecture** | A design approach where servers don’t retain client state between requests, simplifying scalability and fault tolerance. | Kiến trúc phi trạng thái: server không lưu session của client giữa các request, giúp việc scale out và chịu lỗi trở nên cực kỳ dễ dàng. |
| **System resilience** | The system’s capacity to maintain operation and recover quickly from failures or disruptions. | Khả năng tự phục hồi của hệ thống: năng lực duy trì hoạt động hoặc hồi phục nhanh sau các sự cố gián đoạn. |
| **Throughput** | The amount of work or requests a system can process within a given time frame. | Thông lượng: số lượng công việc hoặc requests mà hệ thống xử lý được trong một đơn vị thời gian (RPS, TPS). |
| **Trace** | A record tracking a request’s flow through multiple services, helping identify bottlenecks in distributed architectures. | Dấu vết phân tán: ghi lại đường đi xuyên suốt của một request qua nhiều service để tìm điểm nghẽn. |
| **Traffic** | The volume of incoming requests or transactions the system handles over a specific period. | Lưu lượng truy cập: khối lượng request hoặc transaction đổ vào hệ thống trong một khoảng thời gian. |
| **Usability** | The ease with which users can learn, use, and efficiently complete tasks within a system. | Tính khả dụng: mức độ dễ học, dễ dùng và hoàn thành công việc của người dùng trên giao diện hệ thống. |
| **Uptime** | The percentage of time a system or service is operational; complements downtime as a measure of availability. | Tỷ lệ thời gian hoạt động: phần trăm thời gian hệ thống vận hành trơn tru (đối nghịch với Downtime). |
