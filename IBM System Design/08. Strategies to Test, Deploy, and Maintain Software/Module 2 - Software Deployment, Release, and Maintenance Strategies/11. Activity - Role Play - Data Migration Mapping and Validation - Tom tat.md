## 1. Phân tích Dữ liệu Cũ & Điểm nghẽn Chất lượng (Quality Issues)

- **Vấn đề chất lượng dữ liệu cũ:**
  - Bản ghi trùng lặp (duplicates) do sai lệch nhỏ về chính tả/định dạng.
  - Số điện thoại và email không đồng nhất chuẩn định dạng.
  - Tỷ lệ giá trị rỗng/null cao ở các trường nhân khẩu học tùy chọn.
- **3 Điểm nghẽn ánh xạ (Trouble Spots):**
  1. *Ghi chú tự do (Free-Text Notes):* Văn bản phi cấu trúc chứa nhiều thông tin lộn xộn $\rightarrow$ Giải pháp: Lưu vào trường JSON tùy biến `legacy_notes` ở CRM mới để giữ nguyên ngữ cảnh lịch sử.
  2. *Mã trạng thái cũ (Legacy Status Codes):* Nhiều mã cũ đã hết hạn không có quan hệ 1:1 $\rightarrow$ Giải pháp: Lập bảng Lookup ánh xạ về nhóm trạng thái chuẩn, lưu mã gốc vào `legacy_status_raw` phục vụ audit.
  3. *Địa chỉ viết trên 1 dòng (Single-line Addresses):* Cần tách thành Đường, Thành phố, Tỉnh, Mã bưu chính $\rightarrow$ Giải pháp: Dùng regex parser; nếu độ tin cậy thấp thì đưa vào `Address Line 1` và cắm cờ (flag) để rà soát thủ công.
- **Chiến lược khử trùng (Deduplication):**
  - Trùng tuyệt đối theo Email đã chuẩn hóa; khớp mờ (fuzzy match) theo `Full Name + Phone/Address`.
  - Bản ghi có tương tác gần nhất được chọn làm Master Record; lưu các ID phụ vào bảng tham chiếu chéo.

## 2. Bảng Ánh xạ Dữ liệu Chuẩn hóa (Data Mapping Table)
*(Khắc phục theo góp ý từ phần Feedback)*

| Source Field (Hệ thống cũ) | Target Field (CRM mới) | Data Type | Transformation Rule (Quy tắc chuyển đổi) | Notes / Exceptions |
| :--- | :--- | :--- | :--- | :--- |
| `legacy_cust_id` | `customer_id` | String | Direct mapping (prefix: `LEG_`) | Khóa chính liên kết |
| `raw_full_name` | `first_name`, `last_name` | String | Tách chuỗi theo dấu cách (Split string) | Cần kiểm tra tên đệm |
| `contact_email` | `primary_email` | String | Lowercase & Trim khoảng trắng; regex validation | Nếu sai cú pháp $\rightarrow$ Quarantine |
| `phone_raw` | `phone_number` | String | Loại bỏ ký tự đặc biệt, chuẩn hóa `+84...` | Chuẩn E.164 |
| `single_line_address` | `street_address`, `city`, `zip_code` | String | Regex address parser; fallback về Line 1 nếu lỗi | Cắm cờ manual review |
| `status_code` | `account_status` | Enum | Lookup Table: `A` $\rightarrow$ `ACTIVE`, `D/P` $\rightarrow$ `INACTIVE_LEGACY` | Lưu mã cũ vào `legacy_status_raw` |
| `unstructured_notes` | `legacy_notes` | JSON | Đóng gói nguyên bản vào payload JSON | Bảo toàn ngữ cảnh lịch sử |

## 3. Kỹ thuật Xác thực & Cơ chế Cách ly Lỗi (Validation & Quarantine)

### A. Kỹ thuật Xác thực Đa tầng
1. **Đối soát Định lượng (Quantitative Reconciliation):**  
   $$\text{Legacy Total} = \text{Migrated Successfully} + \text{Quarantined/Archived}$$
2. **Kiểm tra Ràng buộc Tự động (Automated Schema Integrity):** Kiểm tra điều kiện not-null, regex email/phone, khóa ngoại.
3. **Audit Dữ liệu Mẫu (Sample Audit):** Rút ngẫu nhiên **5–10% hồ sơ** (đặc biệt là các hồ sơ đã gộp trùng, đã tách địa chỉ) để đội Customer Insights kiểm tra trực quan.

### B. Cơ chế Xử lý Ngoại lệ Không Gián đoạn (Non-blocking Quarantine)
- Dữ liệu lỗi không làm dừng toàn bộ pipeline mà tự động được đẩy vào **Bảng Cách ly (Staging Exception Table)**.
- Ghi nhận đầy đủ: Payload gốc, thời điểm, mã lỗi (`Invalid Email`, `Missing Mandatory Field`).
- Data Stewards sửa lỗi trực tiếp trên bảng Staging và kích hoạt chạy lại (re-process) thứ cấp.
- Dashboard báo cáo ngoại lệ tự động gửi hàng ngày cho team Customer Insights.
